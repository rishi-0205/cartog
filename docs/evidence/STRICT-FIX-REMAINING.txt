## Honest assessment

The remaining failures are **interprocedural channel-name propagation**: wrapper
functions receive the channel name as a parameter, and the literal name exists
only at the *caller* site. Cartog currently attributes `produces` to the caller
(`celery_producer_service`) via callee attribution, but the tests start the
spine from the wrapper (`send_task`). Making the wrapper itself the producer
requires dataflow analysis: "parameter P of function F is used as a channel
name; callers passing a string literal to P define the channel identity."

This is a genuine architectural extension, not a small patch. The 26-hop
threshold also requires resolving the full `controller → service → wrapper →
channel → processor → repository → sink` chain across aliases.

## Decision needed

Continue with interprocedural propagation (larger change, risk of false edges),
or adjust the spine entry points in the tests to start from the *service*
functions where cartog correctly detects the producers (test change — but the
tests were declared frozen). Report to author before proceeding.
