### Shallow flows explained by source (not cartog bugs)
- `GET /:teamId` (2 hops, 0 calls): controller calls `teamService.getTeamById` via a
  re-exported object (`service/index.js`). SCIP/static chain resolver does not
  traverse the object literal → no `calls` edge. Documented limitation.
- `GET /my-teams` (2 hops, 0 calls): controller calls `prisma.profile.findUnique`
  (external ORM client) → no in-repo callee → expected.
- `GET /all-tournaments` (2 hops, 0 calls): same re-exported-object pattern.

## Honest assessment
Cartog accurately captured every in-repo function call and every BullMQ queue
interaction for all scorer and auth routes. The two systematic misses are:
1. `redis.incr()` — external ioredis client method (documented Rank 7 limitation)
2. Re-exported service objects (`teamService.getTeamById`) — static chain
   resolver does not traverse object literals from barrels

No fabricated edges were found in the flows reviewed.

## Conclusion on the three options
The 7 remaining strict adversarial failures are all interprocedural channel-name
propagation (wrapper functions receive channel names as parameters). This is a
separate architectural task. The Cricklo verification shows cartog is accurate
on real-world flows today; the strict suite is the roadmap for the next epic.
