What the fix does:

* `cartog/render/assets/VENDOR_LOCK.json` pins the five vendored libraries
  (cytoscape 3.34.4, expand-collapse 4.1.1, fcose 2.2.0, layout-base 2.0.1,
  cose-base 2.2.0) by upstream name, version, MIT licence and SHA-256.
  `viewer.js`/`viewer.css` are Cartog's own code, not vendored, and are not in
  the lock. Digests are computed after normalising CRLF/CR to LF so the pin is
  identical on a Windows checkout and on Linux CI; the JSON records that rule.
* `test_vendor_asset_hashes_match_lock` recomputes each digest and asserts the
  lock's file set equals the vendored `.js` set minus `viewer.js`.
* New `cartog/core/toolchain.py` declares `MINIMUM_TOOL_VERSIONS` (node 18.0.0,
  mmdc 10.0.0, scip-python 0.6.0, scip-typescript 0.3.0, madge 6.0.0) and
  `parse_version`/`version_meets_minimum`. `cartog doctor` uses them for every
  tool it probes and prints `<version> (below minimum v<minimum>)` on a WARN
  row instead of a bare PASS.
* `docs/dev/TOOLCHAIN.md` records the tested/pinned versions, the minimums and
  the vendored table; `AGENTS.md` links it (the existing docs-link test
  requires every `docs/dev/*.md` to be linked, which the first full-suite run
  caught and this commit fixes).
