# V2 evidence - index.scip never left in the analyzed repository
Date: 2026-11-23
Branch: feature/verification

Scope: `run_scip_indexer` deletes any `index.scip` that an indexer dropped in
the analyzed repository, and reports it (instead of hiding it) when the file
cannot be deleted. Two tests in `tests/test_scip_pass.py` pin both behaviours.

Files touched:
- `cartog/scip/runner.py`: new `_remove_stray_index()`, called after every
  indexer run; a failed removal is appended to `ScipIndexResult.warnings`.
- `tests/test_scip_pass.py`: `test_stray_index_scip_is_removed`,
  `test_cleanup_failure_is_detected`.

## Tests

Command: venv\Scripts\python.exe -m pytest tests\test_scip_pass.py -k "stray or cleanup" -q
2 passed, 16 deselected in 0.17s            [V2-index-scip-green.txt]

`test_stray_index_scip_is_removed` plants `index.scip` in the target, replaces
`shutil.which` and `run_process` with a fake indexer that writes a valid empty
protobuf index at `--output`, runs `run_scip_indexer`, and asserts the planted
file is gone. `test_cleanup_failure_is_detected` makes `Path.unlink` raise
`PermissionError` for that one file and asserts the run still succeeds but the
warning names `index.scip` and the OS error.

End-to-end note: `scip-python` itself cannot start on this Windows box (see V3,
`node_modules/@sourcegraph/scip-python/.../PythonEnvironment.ts:4` builds
`new RegExp(path.sep, 'g')` from `\` and throws at startup), so the real indexer
path cannot be exercised here. The CLI-level invariant test
`tests/test_cli.py::test_pipeline_leaves_analyzed_repo_untouched` still runs in
the suite with `--no-scip`; the indexer path is proven at unit level with a fake
process boundary, which is exactly the seam V2 changes.
